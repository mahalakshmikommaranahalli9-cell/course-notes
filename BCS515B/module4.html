1. Introduction to First-Order Logic

First-Order Logic (FOL) is a formal language used in Artificial Intelligence to represent objects, properties, relationships and facts about the world.

Propositional logic represents complete statements as simple symbols such as P and Q. However, it cannot directly represent individual objects and relationships between objects.

Propositional Logic: P = "Maha is a student"

First-Order Logic: Student(Maha)

Why do we need FOL?

  • To represent individual objects.
  • To represent properties of objects.
  • To represent relationships between objects.
  • To express general rules.
  • To reason about knowledge.
Easy memory:
Propositional Logic → Whole statements
First-Order Logic → Objects + Properties + Relations + Quantifiers

2. Syntax of First-Order Logic

Syntax specifies how valid FOL expressions are constructed.

2.1 Constants

A constant represents a particular object.

Maha
Bengaluru
JIT
5

2.2 Variables

Variables represent unspecified objects.

x, y, z

2.3 Predicates

A predicate represents a property or relationship.

Student(Maha)
Likes(Maha, AI)

Here Student is a unary predicate and Likes is a binary predicate.

2.4 Functions

Functions return an object.

FatherOf(Maha)
ManagerOf(Employee1)

2.5 Terms

Terms refer to objects.

  • Constants
  • Variables
  • Functions applied to terms

2.6 Quantifiers

Quantifiers tell us how many objects satisfy a statement.

Universal Quantifier — ∀

Means "for all".

∀x Student(x) → Learner(x)

Meaning: Every student is a learner.

Existential Quantifier — ∃

Means "there exists at least one".

∃x Student(x) ∧ Intelligent(x)

Meaning: There exists at least one student who is intelligent.

2.7 Logical Connectives

Symbol Name Meaning
¬ NOT Negation
∧ AND Both must be true
∨ OR At least one is true
→ Implication If...then...
↔ Biconditional If and only if

3. Semantics of First-Order Logic

Semantics describes the meaning of FOL expressions.

Domain

The domain is the collection of objects being discussed.

Domain = {Maha, Ravi, Priya}

Interpretation

Interpretation tells us what constants, predicates and functions mean in a particular domain.

Example

Domain = Students

Student(Maha)

The interpretation tells us that Maha is an object in the domain and Student is a property.

Free and Bound Variables

A variable is bound when it is controlled by a quantifier.

∀x Student(x)

Here x is bound.

A variable without a quantifier is called a free variable.

Student(x)

Here x is free.

4. Representing Knowledge using FOL

One of the most important applications of FOL in AI is converting natural-language statements into logical form.

Example 1 — Every student is a learner

Step 1: Identify objects
Student → object/property
Learner → property
Step 2: Identify quantifier
"Every" means universal quantifier.
Step 3: Write FOL
∀x (Student(x) → Learner(x))

Example 2 — Some students are intelligent

Step 1
"Some" means existential quantifier.
Step 2
Identify properties:
Student(x)
Intelligent(x)
Step 3
∃x (Student(x) ∧ Intelligent(x))

Example 3 — Every teacher teaches a subject

Step 1: Identify objects
Teacher → person
Subject → object
Step 2: Identify relationship
Teaches(teacher, subject)
Step 3: Add universal quantifier
∀x (Teacher(x) → ∃y (Subject(y) ∧ Teaches(x,y)))

Example 4 — Maha likes AI

Likes(Maha, AI)

Example 5 — Every programmer knows Python

∀x (Programmer(x) → Knows(x, Python))

Example 6 — There is a student who knows AI

∃x (Student(x) ∧ Knows(x, AI))

Example 7 — No student is a teacher

∀x (Student(x) → ¬Teacher(x))

Example 8 — All dogs are animals

∀x (Dog(x) → Animal(x))

Example 9 — Some animals are dogs

∃x (Animal(x) ∧ Dog(x))
Exam Trick:
Every / All → ∀
Some / At least one / There exists → ∃
No → Usually represented using implication + negation

6. Knowledge Engineering

Knowledge Engineering is the process of building a knowledge base that allows an AI system to reason about a particular domain.

Steps of Knowledge Engineering

  1. Identify the task.
  2. Assemble relevant knowledge.
  3. Decide the vocabulary.
  4. Encode general knowledge.
  5. Encode a specific instance.
  6. Pose queries to the knowledge base.
  7. Debug the knowledge base.

Example — University Knowledge Base

Step 1: Identify the domain
University / College
Step 2: Define vocabulary
Student(x)
Teacher(x)
Studies(x,y)
Teaches(x,y)
Step 3: Add facts
Student(Maha)
Studies(Maha, AI)
Step 4: Add rules
∀x (Student(x) → Learner(x))
Step 5: Query
Query:
Learner(Maha)?
Since Student(Maha) is true and every student is a learner, the answer is TRUE.

7. Unification

Unification is the process of finding substitutions that make two logical expressions identical.

Unification → Make two expressions the same

Substitution

A substitution replaces variables with constants, variables or terms.

θ = {x / Maha}

This means replace x with Maha.

Example 1 — Simple Unification

Unify:

Student(x)
Student(Maha)
Step 1
Predicates are the same:
Student = Student
Step 2
Compare arguments:
x = Maha
Step 3
Therefore:
θ = {x / Maha}
MGU = {x/Maha}
MGU means Most General Unifier.

Example 2 — Two Variables

Unify:

Likes(x, AI)
Likes(Maha, AI)
Step 1
Predicates are same:
Likes = Likes
Step 2
First arguments:
x = Maha
Step 3
Second arguments:
AI = AI
Already equal.
θ = {x / Maha}

Example 3 — Variable with Variable

Unify:

Knows(x, y)
Knows(Maha, AI)
Step 1
First argument:
x = Maha
Step 2
Second argument:
y = AI
θ = {x / Maha, y / AI}

Example 4 — Function Unification

Unify:

Likes(x, FatherOf(y))
Likes(Maha, FatherOf(Ravi))
Step 1
Predicates are identical:
Likes = Likes
Step 2
First arguments:
x = Maha
Step 3
Second arguments:
FatherOf(y) = FatherOf(Ravi)
Step 4
Therefore:
y = Ravi
θ = {x / Maha, y / Ravi}

Example 5 — Cannot Unify

Try to unify:

Student(Maha)
Teacher(Maha)

Predicates are different.

Student ≠ Teacher

Therefore, these expressions cannot be unified.

Important Unification Rules

  • Predicate names must match.
  • Number of arguments must match.
  • Constants must match exactly.
  • Variables can be substituted.
  • Function names and structures must match.

8. Forward Chaining

Forward chaining is a data-driven inference technique. It starts with known facts and repeatedly applies rules to derive new facts.

Facts → Rules → New Facts → More Rules → Conclusion

Basic Rule Format

P ∧ Q → R

If P and Q are true, then R can be concluded.

Forward Chaining Algorithm

  1. Start with initial facts.
  2. Find a rule whose conditions are satisfied.
  3. Apply the rule.
  4. Add the new fact to the knowledge base.
  5. Repeat the process.
  6. Stop when the query is derived or no new facts can be generated.

🔥 Solved Problem 1 — Simple Forward Chaining

Given:

Fact 1: Student(Maha)
Rule 1: Student(x) → Learner(x)
Rule 2: Learner(x) → Intelligent(x)

Query: Intelligent(Maha)?

Step 1: Initial facts
Student(Maha)
Step 2: Apply Rule 1
Student(x) → Learner(x)

Substitute:
x = Maha

Therefore:
Learner(Maha)
Step 3: Apply Rule 2
Learner(x) → Intelligent(x)

Substitute:
x = Maha

Therefore:
Intelligent(Maha)
Answer: TRUE
Intelligent(Maha) has been derived.

🔥 Solved Problem 2 — Multiple Facts

Facts:

Student(Maha)
Studies(Maha, AI)
Smart(Maha)

Rules:

Student(x) ∧ Studies(x, AI) → LearnsAI(x)

LearnsAI(x) ∧ Smart(x) → GoodStudent(x)

Query: GoodStudent(Maha)?

Step 1: Check Rule 1
Student(Maha) → TRUE
Studies(Maha, AI) → TRUE

Therefore:
LearnsAI(Maha)
Step 2: Check Rule 2
LearnsAI(Maha) → TRUE
Smart(Maha) → TRUE

Therefore:
GoodStudent(Maha)
Answer: TRUE

🔥 Solved Problem 3 — Forward Chaining Chain

Facts:

A

Rules:

A → B
B → C
C → D
D → E

Query: E?

Step 1
Initial fact:
A
Step 2
Apply A → B
Therefore B.
Step 3
Apply B → C
Therefore C.
Step 4
Apply C → D
Therefore D.
Step 5
Apply D → E
Therefore E.
Answer: TRUE
E is derived through forward chaining.

🔥 Solved Problem 4 — Query Not Derivable

Facts:

Student(Maha)

Rule:

Student(x) → Learner(x)

Query: Doctor(Maha)?

Step 1
We know:
Student(Maha)
Step 2
Apply the only rule:
Student(x) → Learner(x)

Derive:
Learner(Maha)
Step 3
Check whether:
Doctor(Maha)
can be derived.
No rule derives Doctor(Maha).

Therefore the query is not derivable from the given knowledge base.

9. Forward Chaining vs Backward Chaining

Feature Forward Chaining Backward Chaining
Approach Data-driven Goal-driven
Starts with Known facts Goal/query
Direction Facts → Conclusion Goal → Required facts
Useful when Many facts are available Specific goal is known
Memory Trick:

Forward = Start from Facts and move Forward.
Backward = Start from Goal and work Backward.

11. Important VTU Exam Questions

2-Mark Questions

1. What is First-Order Logic?
First-Order Logic is a formal language used to represent objects, properties, relationships and quantified statements.
2. What is a predicate?
A predicate represents a property or relationship involving one or more objects.
3. What is a quantifier?
A quantifier specifies the number of objects for which a logical statement is true.
4. Define unification.
Unification is the process of finding substitutions that make two logical expressions identical.
5. What is forward chaining?
Forward chaining is a data-driven inference method that starts with known facts and applies rules to derive new facts.

12. VTU Answer-Writing Format

For 10 Marks

  1. Start with definition.
  2. Explain the concept.
  3. Write important components.
  4. Give formulas.
  5. Draw/write a suitable example.
  6. Solve the example step-by-step.
  7. Write the final result clearly.
Golden Rule: For numerical/logical problems, never write only the final answer. Show the substitution or inference steps.
