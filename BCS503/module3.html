2. Context-Free Grammar

2.1 Definition

A Context-Free Grammar is a formal system used to generate strings belonging to a context-free language.

A CFG is represented by: 

G = (V, Σ, P, S)
  • V = Set of variables / non-terminals
  • Σ = Set of terminals
  • P = Set of production rules
  • S = Start symbol

2.2 Production Rule

A CFG production generally has the form: 

A → α

where A is one variable and α is a string containing terminals and variables.

2.3 Example 

S → aSb | ε

This grammar generates: 

ε
ab
aabb
aaabbb
aaaabbbb
...

Therefore: 

L(G) = { aⁿbⁿ | n ≥ 0 }

3. Complete CFG Construction Problems

Problem 1 — Construct CFG for L = { aⁿbⁿ | n ≥ 0 }

Step 1 — Understand the language

The language contains equal numbers of a's and b's. All a's occur before all b's. Examples: 

ε
ab
aabb
aaabbb
aaaabbbb
Step 2 — Find the recursive pattern

For every additional a we need one additional b. Therefore we put one a on the left and one b on the right. 

S → aSb
Step 3 — Add the stopping condition

When no more pairs are required, the grammar must stop. Since n can be zero: 

S → ε
Step 4 — Write the complete grammar 
S → aSb | ε
Step 5 — Verify string "aaabbb" 
S
⇒ aSb
⇒ aaSbb
⇒ aaaSbbb
⇒ aaaεbbb
⇒ aaabbb
Final Answer: 
G = ({S}, {a,b}, {S → aSb | ε}, S)

Therefore the grammar generates exactly the language {aⁿbⁿ | n ≥ 0}.

Problem 2 — Construct CFG for L = { aⁿbᵐ | n ≥ 1, m ≥ 1 }

Step 1 — Understand the language

There must be at least one a and at least one b. The number of a's and b's does not have to be equal. Examples: 

ab
aab
abb
aaabb
aaaabbbb
Step 2 — Generate one or more a's 
A → aA | a
Step 3 — Generate one or more b's 
B → bB | b
Step 4 — Join them 
S → AB
Step 5 — Complete grammar 
S → AB

A → aA | a

B → bB | b
Step 6 — Derive "aaabbb" 
S
⇒ AB
⇒ aAB
⇒ aaAB
⇒ aaaB
⇒ aaabB
⇒ aaabbB
⇒ aaabbb
Final Answer: 
S → AB
A → aA | a
B → bB | b

Step 1 — Understand palindrome structure

A palindrome reads the same from left to right and right to left. Examples:

S → aSa
S → bSb

We need even-length and odd-length palindromes. 

S → ε | a | b

S

Problem 4 — Construct CFG for Balanced Parentheses

Step 1 — Empty string

The empty string is balanced. 

S → ε
Step 2 — Put parentheses around a balanced string 
S → (S)

S → SS
Step 4 — Final grammar 
S → SS | (S) | ε
Step 5 — Derive "(())" 
S
⇒ (S)
⇒ ((S))
⇒ (())

S → SS | (S) | ε

5. Parse Trees

A parse tree is a tree representation of how a string is derived from a grammar.

  • Root = Start symbol
  • Internal nodes = Variables
  • Leaves = Terminals or ε
  • Read leaves from left to right to obtain the string

Problem 7 — Parse Tree for "aabb"

Grammar: 

S → aSb | ε
Step 1 — Root 
        S
Step 2 — First expansion 
          S
        / | \
       a  S  b
Step 3 — Expand inner S 
            S
          / | \
         a  S  b
           / | \
          a  S  b
Step 4 — Replace final S by ε 
            S
          / | \
         a  S  b
           / | \
          a  ε  b
Step 5 — Read the leaves 
a a ε b b

ε contributes no symbol. Therefore: 

aabb
Final Answer:

The parse tree generates the string aabb.

6. Ambiguity in Grammars

6.1 Definition

A grammar is ambiguous if at least one string in its language has two or more distinct parse trees.

Equivalently, the string has:

  • Two different leftmost derivations
  • or two different rightmost derivations
  • or two different parse trees

Problem 8 — Prove that the Grammar is Ambiguous

Consider: 

E → E + E
E → E * E
E → id

Show that: 

id + id * id

is ambiguous.

Step 1 — First derivation

Choose + as the top-level operation. 

E
⇒ E + E
⇒ id + E
⇒ id + E * E
⇒ id + id * E
⇒ id + id * id
Step 2 — Second derivation

Choose * as the top-level operation. 

E
⇒ E * E
⇒ E + E * E
⇒ id + E * E
⇒ id + id * E
⇒ id + id * id
Step 3 — Compare the structures

First interpretation: 

id + (id * id)

Second interpretation: 

(id + id) * id
Conclusion:

The same string can have two distinct parse structures. Therefore the grammar is: 

AMBIGUOUS

Problem 9 — Grammar with Expression Precedence

A common way to remove the arithmetic ambiguity is to separate expression and multiplication levels.

Step 1 — Expression 
E → E + T | T
Step 2 — Term 
T → T * F | F
Step 3 — Factor 
F → id | (E)
Final Grammar: 
E → E + T | T

T → T * F | F

F → id | (E)

This grammar structurally gives multiplication a deeper level than addition.

7. Pushdown Automata

7.1 Why do we need PDA?

A finite automaton has only a finite number of states and cannot remember an unlimited count. For example: 

L = { aⁿbⁿ | n ≥ 1 }

A PDA solves this using a stack.

7.2 PDA Definition 

M = (Q, Σ, Γ, δ, q₀, Z₀, F)
Component Meaning
Q Finite set of states
Σ Input alphabet
Γ Stack alphabet
δ Transition function
q₀ Initial state
Z₀ Initial stack symbol
F Set of final states

7.3 Transition Notation 

δ(q, input, stack-top)
=
(new-state, new-stack-content)

Example: 

δ(q0, a, Z0)
=
(q0, AZ0)

Meaning: When the PDA is in q0, reads a, and sees Z0 on the stack, it stays in q0 and pushes A.

8. Complete PDA Construction Problems

Problem 10 — Construct PDA for L = { aⁿbⁿ | n ≥ 1 }

Step 1 — Understand the language

The string must contain:

  • One or more a's
  • Followed by one or more b's
  • Number of a's = number of b's

Examples: 

ab
aabb
aaabbb
aaaabbbb
Step 2 — Decide what the stack stores

For every a that we read, push one A onto the stack. 

a → PUSH A
Step 3 — Process b's

For every b, remove one A from the stack. 

b → POP A
Step 4 — Define states 
q0 = reading a's

q1 = reading b's

qf = final state
Step 5 — Define stack alphabet 
Γ = {A, Z0}

Z0 is the bottom stack marker.

Step 6 — Construct transitions
Current Input Stack Top Next Action
q0 a Z0 q0 Push A
q0 a A q0 Push A
q0 b A q1 Pop A
q1 b A q1 Pop A
q1 ε Z0 qf Accept
Step 7 — Test with aabb 
Input = aabb

Initial:
(q0, aabb, Z0)

Read first a: 

(q0, abb, AZ0)

Read second a: 

(q0, bb, AAZ0)

Read first b: 

(q1, b, AZ0)

Read second b: 

(q1, ε, Z0)

Take ε transition: 

(qf, ε, Z0)
Final Answer:

The PDA accepts exactly the strings whose number of a's equals the number of b's, with all a's occurring before b's. 

L = { aⁿbⁿ | n ≥ 1 }

Problem 11 — Complete PDA Trace for "aaabbb"

Use the PDA from Problem 10.

Step 1 — Initial configuration 
(q0, aaabbb, Z0)
Step 2 — Read first a 
(q0, aabbb, AZ0)
Step 3 — Read second a 
(q0, abbb, AAZ0)
Step 4 — Read third a 
(q0, bbb, AAAZ0)
Step 5 — Read first b 
(q1, bb, AAZ0)
Step 6 — Read second b 
(q1, b, AZ0)
Step 7 — Read third b 
(q1, ε, Z0)
Step 8 — Enter final state 
(qf, ε, Z0)
Conclusion:

Three A's were pushed for three a's and exactly three A's were popped for three b's. Therefore: 

aaabbb → ACCEPTED

Problem 12 — Show why "aabbb" is rejected

Step 1 — Read first a 
(q0, aabbb, Z0)
→
(q0, abbb, AZ0)
Step 2 — Read second a 
(q0, abbb, AZ0)
→
(q0, bbb, AAZ0)
Step 3 — Read first b 
(q0, bbb, AAZ0)
→
(q1, bb, AZ0)
Step 4 — Read second b 
(q1, bb, AZ0)
→
(q1, b, Z0)
Step 5 — Third b arrives

The stack contains only Z0. There is no A available to pop. Therefore the transition for the third b is not possible.

Final Result: 
aabbb → REJECTED

Because: 

Number of a's = 2

Number of b's = 3

9. Languages of a PDA

Acceptance by Final State

A string is accepted if the complete input is consumed and the PDA enters a final state.

Acceptance by Empty Stack

A string is accepted if the complete input is consumed and the stack becomes empty according to the PDA's convention.

Important: For nondeterministic PDAs, acceptance by final state and acceptance by empty stack characterize the same class of context-free languages.

10. Equivalence of CFG and PDA

Important theorem:

A language is context-free if and only if some pushdown automaton accepts the language.

10.1 CFG → PDA

The PDA uses its stack to simulate the derivation of the CFG.

Problem 14 — Convert CFG S → aSb | ε to a PDA

Step 1 — Start with S on stack 
Stack:

S
Step 2 — Simulate grammar production

The grammar contains: 

S → aSb
S → ε

Therefore the PDA can replace S by either aSb or ε. 

δ(q, ε, S) → (q, aSb)

δ(q, ε, S) → (q, ε)
Step 3 — Match terminal a 
δ(q, a, a) → (q, ε)
Step 4 — Match terminal b 
δ(q, b, b) → (q, ε)
Step 5 — Test with "aabb" 
Stack:
S

Apply S → aSb

Stack:
aSb

Read a

Stack:
Sb

Apply S → aSb

Stack:
aSbb

Read a

Stack:
Sbb

Apply S → ε

Stack:
bb

Read b

Stack:
b

Read b

Stack:
empty / bottom marker

Accept
Conclusion:

The PDA simulates a derivation of the CFG and accepts the strings generated by it.

10.2 PDA → CFG

The reverse construction converts a PDA into a CFG whose variables describe possible stack computations between states.

Exam Writing Point

For a theoretical question asking for the equivalence proof, write:

  1. Every CFG can be simulated by a PDA.
  2. Every PDA can be represented by an equivalent CFG.
  3. Therefore the languages generated by CFGs are exactly the languages accepted by NPDAs. 
CFL = Languages accepted by NPDA

11. Deterministic Pushdown Automata

11.1 Definition

A Deterministic Pushdown Automaton, or DPDA, is a PDA where the next action is uniquely determined by the current state, input situation and stack top.

11.2 PDA vs DPDA

Feature PDA / NPDA DPDA
Nondeterminism Allowed Not generally allowed
Possible transitions Can have choices At most one applicable move
Languages All context-free languages Deterministic context-free languages
Power More general Restricted compared with NPDA

Problem 15 — Why aⁿbⁿ can be handled deterministically

Step 1 — Observe the input structure 
aaaabbbb
^^^^ ^^^^
 a's  b's

All a's occur first, then b's.

Step 2 — Push during a-phase

For every a, push A.

Step 3 — Change phase at first b

When the first b is encountered, move to the popping state.

Step 4 — Pop during b-phase

For every b, pop one A.

Step 5 — Accept

If all input is consumed and the stack reaches the bottom marker, accept.

Conclusion:

The input symbols themselves determine the phase change, so no guess is required for this language.

Important exam correction: Do not write: 
Every CFL can be accepted by a DPDA.

That statement is false. The correct statement is: 

Every CFL can be accepted by an NPDA.

DPDA recognizes deterministic
context-free languages.

12. Finite Automaton vs PDA

Feature Finite Automaton PDA
Memory Finite states Stack + finite states
Recognizes Regular languages Context-free languages (NPDA)
Can recognize aⁿbⁿ? No Yes
Unbounded memory No Stack provides theoretical unbounded storage
