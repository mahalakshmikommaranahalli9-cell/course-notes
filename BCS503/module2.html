2. Regular Expressions — Complete Theory

2.1 Definition

A regular expression (RE) is a formal notation used to describe a regular language over an alphabet. It is constructed recursively from basic symbols using operations such as union, concatenation and Kleene star.

If the alphabet is Σ = {a,b}, expressions can be constructed from a, b, ε and ∅ using the allowed operators.

Basic expressions

ExpressionMeaning
∅Language containing no strings.
εLanguage containing only the empty string.
aLanguage containing the single string a.

2.2 Union

For regular expressions R and S, R + S represents the union of their languages.

L(R + S) = L(R) ∪ L(S)
Example: a+b accepts either a or b.

2.3 Concatenation

Concatenation joins a string from R with a string from S.

L(RS) = L(R)L(S)
Example: ab accepts exactly the string ab.

2.4 Kleene Star

The Kleene star means zero or more repetitions.

L(R*) = {ε, strings formed using one or more repetitions of R}

a* represents:

ε, a, aa, aaa, aaaa, ...

2.5 Operator Precedence

When parentheses are absent, use:

  1. Star (*) has highest precedence.
  2. Concatenation has next precedence.
  3. Union (+) has lowest precedence.

a+bc* means:

a + (b(c*))

2.6 Important RE Construction Patterns

Language requirementRegular Expression
All strings over {a,b}(a+b)*
Strings ending in a(a+b)*a
Strings beginning with aa(a+b)*
Strings containing ab(a+b)*ab(a+b)*
Exactly one 1 over {0,1}0*10*
Exactly two 1s0*10*10*
Even number of 1s0*(10*10*)*
Odd number of 1s0*10*(10*10*)*

Solved Example 1 — RE for strings ending in 1

Language: All strings over {0,1} that end in 1.

The part before the final 1 can contain anything.

Anything over {0,1}: (0+1)*

Final symbol: 1

Answer: (0+1)*1

Solved Example 2 — RE for strings containing at least one 1

Anything before 1 + the required 1 + anything after it:

(0+1)*1(0+1)*

Solved Example 3 — RE for exactly two a's

Anything except a before the first a is b*.

Then first a, then any number of b's, then second a, then b's.

Answer: b*ab*ab*

3. Relationship Between Finite Automata and Regular Expressions

3.1 Fundamental Result

Finite automata and regular expressions describe the same class of languages: regular languages.

Regular Expression ⇄ Finite Automaton

Therefore, a regular expression can be converted into an equivalent finite automaton, and a finite automaton can be converted into an equivalent regular expression.

3.2 RE → ε-NFA — Construction Idea

A standard construction creates an ε-NFA for each regular expression and combines these small automata according to the RE operation.

RE operationConstruction idea
Symbol aOne transition labelled a.
R + Sε-branch from a new start to R and S.
RSConnect final of R to start of S using ε.
R*Add ε paths allowing zero or repeated copies.

Solved Example 4 — Construct automaton for a+b

Create a new start state q0.

From q0, use ε-transitions to two branches.

First branch reads a and reaches a final state.

Second branch reads b and reaches a final state.

This accepts exactly {a,b}.

3.3 Finite Automaton → Regular Expression

One common method is state elimination. The idea is to remove states while replacing paths through the removed state by an equivalent regular-expression label.

State Elimination Formula

Rij(new) = Rij(old) + Rik(Rkk)*Rkj

Here k is the state being eliminated, while i and j are the remaining states.

General Procedure

  1. Convert the automaton into a suitable generalized transition graph.
  2. Choose an intermediate state to eliminate.
  3. Update paths passing through that state.
  4. Repeat until only the required start-to-final path remains.
  5. The resulting label is the equivalent regular expression.

Solved Example 5 — State Elimination Idea

Suppose a path from q0 to q1 has label a, q1 has a loop b, and q1 reaches q2 using c.

The path from q0 to q2 is:

ab*c

because q1 can be visited zero or more times through the b-loop.

4. Pumping Lemma for Regular Languages

4.1 Why Pumping Lemma?

Finite automata have only a finite number of states. When a sufficiently long string is processed, some state must be visited more than once. The repeated portion forms a loop. That loop can be repeated more times or removed while remaining within the structure of a regular automaton.

The Pumping Lemma formalizes this observation. It is mainly used to show that a language is not regular.

4.2 Statement

If L is a regular language, then there exists a positive integer p such that every string w ∈ L with |w| ≥ p can be written as:

w = xyz

such that:

1. |xy| ≤ p
2. |y| > 0
3. xyⁱz ∈ L for every i ≥ 0

Meaning of the three conditions

  • |xy| ≤ p: the pumped part occurs within the first p symbols.
  • |y| > 0: the pumped part cannot be empty.
  • xyⁱz ∈ L: pumping y any number of times must keep the string in L if L is regular.

4.3 Standard Proof Strategy

  1. Assume the language is regular.
  2. Let p be the pumping length.
  3. Choose a string w ∈ L with |w| ≥ p.
  4. Consider every valid split w=xyz satisfying the lemma.
  5. Use |xy|≤p to restrict the possible location of y.
  6. Choose i=0 or i=2.
  7. Show that xyⁱz ∉ L.
  8. This contradicts the pumping lemma.
  9. Therefore the original assumption was false.
Important: You cannot simply choose a convenient split. The proof must handle every split satisfying the pumping-lemma conditions.

Solved Problem 1 — Prove L = {aⁿbⁿ | n ≥ 0} is not regular

Step 1: Assume L is regular.

Then a pumping length p exists.

Step 2: Choose the string.

w = aᵖbᵖ

Clearly w ∈ L and |w|=2p ≥ p.

Step 3: Apply |xy|≤p.

The first p symbols are all a's. Therefore y consists only of a's.

Let y=aᵏ, where k>0.

Step 4: Pump down.

Choose i=0.

xy⁰z = xz = aᵖ⁻ᵏbᵖ

Now the number of a's is less than the number of b's.

Therefore:

xz ∉ L

Step 5: Contradiction.

The pumping lemma says xyⁱz must remain in L for every i≥0.

Therefore L is not regular.

Solved Problem 2 — Prove L = {0ⁿ1ⁿ | n ≥ 0} is not regular

Assume L is regular with pumping length p.

Choose w=0ᵖ1ᵖ.

Since |xy|≤p, y contains only zeros.

Pump y down using i=0.

The number of zeros becomes smaller than the number of ones.

Hence the resulting string is not in L.

Therefore L is not regular.

Solved Problem 3 — Why is {aⁿbⁿcⁿ | n≥0} not regular?

Assume the language is regular and choose w=aᵖbᵖcᵖ. Because |xy|≤p, y lies entirely in the first block of a's. Pumping y changes the number of a's without changing the numbers of b's and c's. The equality requirement is broken.

Contradiction. Hence the language is not regular.

5. Closure Properties of Regular Languages

A family of languages is said to be closed under an operation if applying that operation to languages in the family produces another language that is still in the family.

OperationRegular languages closed?Idea
UnionYesUse product construction or combine automata.
IntersectionYesProduct automaton.
ComplementYesComplete DFA and swap final/non-final states.
DifferenceYesL1−L2 = L1 ∩ complement(L2).
ConcatenationYesConnect automata using ε-transitions in NFA construction.
Kleene starYesAdd ε paths for zero or more repetitions.
ReversalYesReverse transitions using an NFA construction.

Solved Problem 4 — Prove regular languages are closed under complement

Let L be regular. Then there exists a DFA M accepting L. First ensure that M is complete, meaning every state has a transition for every alphabet symbol.

Create M' by changing every final state of M into a non-final state and every non-final state into a final state.

M' accepts exactly the strings that M rejects.

Therefore the complement of a regular language is regular.

6. Equivalence of Automata

Definition

Two automata M1 and M2 are equivalent if they accept exactly the same set of strings.

M1 ≡ M2 ⇔ L(M1)=L(M2)

Ways to establish equivalence

  • Compare their recognized languages.
  • Construct the symmetric-difference product and check emptiness.
  • Minimize both DFAs and compare the resulting structures, with suitable state correspondence.

7. DFA Minimization — Full Theory

Why minimize a DFA?

A DFA may contain states that are unreachable or states that behave identically for all possible future inputs. Minimization removes unnecessary states while preserving the language recognized by the DFA.

Important terms

  • Reachable state: a state that can be reached from the initial state.
  • Equivalent states: no input string can distinguish their behavior with respect to acceptance.
  • Distinguishable states: there exists an input string that causes one state to accept and the other to reject.

7.1 Table-Filling Method

  1. Remove unreachable states.
  2. List every unordered pair of remaining states.
  3. Mark pairs in which one state is final and the other is non-final.
  4. For each unmarked pair (p,q), examine every input symbol.
  5. If δ(p,a) and δ(q,a) form an already marked pair, mark (p,q).
  6. Repeat until no new pair is marked.
  7. Unmarked pairs represent equivalent states.
  8. Merge equivalent states.

Worked Minimization Example

Consider states:

Q = {A,B,C,D,E}

Suppose:

  • A is the initial state.
  • D and E are final states.
  • All states are reachable.

Start by making pairs:

(A,B), (A,C), (A,D), (A,E),
(B,C), (B,D), (B,E),
(C,D), (C,E),
(D,E)

Immediately mark every pair containing exactly one final and one non-final state:

(A,D), (A,E), (B,D), (B,E), (C,D), (C,E)

Then examine every remaining pair using the transition table of the specific DFA. If a transition leads to a previously marked pair, mark the current pair. Continue until no new pair can be marked.

For an actual VTU numerical problem, always use the given transition table. Do not guess whether two states are equivalent merely because they look similar.

7.2 Partition Refinement Method

Another minimization method starts with two groups:

P0 = {Final states, Non-final states}

Then repeatedly split a group whenever its states transition into different groups for some input symbol. Continue until no group can be split. Each final group becomes one state of the minimized DFA.

8. Applications of Regular Expressions

Text Searching

REs can locate patterns in large text files.

Lexical Analysis

Compilers use regular-language concepts to identify tokens such as identifiers, numbers and keywords.

Input Validation

Regular expressions are commonly used for checking whether input follows a required pattern.

Log Analysis

Patterns can be searched in server and application logs.

Practical example: 
^[A-Za-z][A-Za-z0-9]*$

This practical regex describes a simple identifier beginning with a letter and followed by zero or more letters/digits.

10. Common Mistakes

  • Do not confuse ε with ∅.
  • In pumping-lemma proofs, do not select only one convenient split without justification.
  • Remember that pumping lemma is normally used to prove non-regularity; satisfying it does not by itself prove regularity.
  • For DFA minimization, remove unreachable states first.
  • For complement construction, the DFA must be complete.
  • Do not confuse RE notation used in formal language theory with every feature of programming-language regex engines.
