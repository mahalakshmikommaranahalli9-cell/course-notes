1. Introduction to Turing Machines

1.1 What is a Turing Machine?

A Turing Machine (TM) is a mathematical model of computation introduced by Alan Turing.

It is more powerful than finite automata and pushdown automata because it has an unlimited tape that can be used as memory.

A simple representation is: 

        Read / Write Head
              ↓
... | 0 | 1 | 1 | 0 | 1 | B | B | B | ...
              ↑
            Tape

The head can:

  • Read a symbol.
  • Write a symbol.
  • Move Left.
  • Move Right.

1.2 Why do we need Turing Machines?

  • To model general computation.
  • To study what computers can and cannot solve.
  • To define decidable and undecidable problems.
  • To study algorithms formally.
  • To understand the limits of computation.

1.3 Difference between FA, PDA and TM

Feature FA PDA TM
Memory Finite states Stack Infinite tape
Read input One direction One direction Can move L/R
Write memory No Stack operations Yes
Power Regular languages Context-Free Languages General computation

2. Formal Definition of Turing Machine

A Turing Machine is represented using a 7-tuple: 

M = (Q, Σ, Γ, δ, q₀, B, F)

2.1 Components

Symbol Meaning
Q Finite set of states
Σ Input alphabet
Γ Tape alphabet
δ Transition function
q₀ Initial state
B Blank symbol
F Set of final states

2.2 Transition Function

A common form of transition function is: 

δ(q, X) = (p, Y, D)

Meaning:

  • Current state = q
  • Read X
  • Write Y
  • Move in direction D
  • Enter state p

where: 

D = L or R

3. Turing Machine Transition Table

A transition table tells the machine what to do for each current state and tape symbol.

Example

Current State Read Write Move Next State
q0 0 X R q1
q1 0 0 R q1
q1 1 Y L q2

The first row means: 

If machine is in q0
and reads 0,

write X,
move Right,
go to q1.

4. General Method to Construct a Turing Machine

Step 1 — Understand the language

First identify exactly what condition the input must satisfy.

Step 2 — Decide what must be remembered

Use tape symbols such as: 

X
Y
A
B

to mark symbols that have already been processed.

Step 3 — Create states

Each state should perform one clear task.

Step 4 — Write transitions

For every relevant symbol specify: 

Read
Write
Move
Next state

Step 5 — Test using a small input

Always trace the machine manually.

5. Solved Problem 1 — TM for 0ⁿ1ⁿ

Problem

Construct a Turing Machine for: 

L = { 0ⁿ1ⁿ | n ≥ 1 }

Examples accepted: 

01
0011
000111
00001111

Examples rejected: 

001
011
00111
0101

5.1 Basic idea

We match every 0 with one 1.

Use: 

X = marked 0
Y = marked 1

Algorithm:

  1. Find the first unmarked 0.
  2. Change it to X.
  3. Move right until an unmarked 1 is found.
  4. Change that 1 to Y.
  5. Return to the left side.
  6. Repeat.
  7. When no unmarked 0 remains, check that only Y remains.
  8. Accept if valid.

5.2 States

State Purpose
q0 Find an unmarked 0
q1 Find matching 1
q2 Return to left
q3 Final checking
q_accept Accept
q_reject Reject

5.3 Transition table

State Read Write Move Next
q0 0 X R q1
q0 X X R q0
q0 Y Y R q3
q1 0 0 R q1
q1 Y Y R q1
q1 1 Y L q2
q2 0 0 L q2
q2 X X L q2
q2 Y Y L q2
q2 B B R q0
q3 Y Y R q3
q3 B B R q_accept
q3 0 0 R q_reject

5.4 Trace for input 0011

Step 1 
0011
^
q0

First 0 is marked: 

X011
Step 2

Move right and find the first 1. 

X0Y1
Step 3

Return to beginning. 

X0Y1
^
q0
Step 4

Mark the second 0: 

XXY1
Step 5

Find the remaining 1: 

XXYY
Step 6

No unmarked 0 remains. Only Y symbols remain. 

XXYY → ACCEPT
Final result: 
0011 ∈ L

6. Solved Problem 2 — TM for Palindrome

Problem

Construct a TM that accepts binary palindromes. 

L = { w | w = reverse(w) }

Examples: 

ε
0
1
00
11
010
101
0110
1001

Examples rejected: 

01
10
001
011
0100

6.1 Main idea

Compare the first and last unmarked symbols.

If they are equal: 

mark both

Then repeat for the smaller remaining string.

Use: 

X = processed 0
Y = processed 1

6.2 Algorithm

  1. Find the first unmarked symbol.
  2. Remember whether it is 0 or 1.
  3. Mark it.
  4. Move to the right end.
  5. Find the last unmarked symbol.
  6. Compare it with the remembered symbol.
  7. If they are different, reject.
  8. If they are equal, mark it.
  9. Return to the left.
  10. Repeat.
  11. If no unmarked symbol remains, accept.

6.3 States

State Purpose
q0 Find first unmarked symbol
q1 First symbol was 0
q2 First symbol was 1
q3 Return left after matching 0
q4 Return left after matching 1
q_accept Accept
q_reject Reject

6.4 Conceptual transition table

State Read Action
q0 0 Mark 0 as X and search for matching last symbol
q0 1 Mark 1 as Y and search for matching last symbol
q0 X/Y Continue scanning
q0 B Accept
q1 0 Search right for last unmarked symbol
q1 1 Reject if it is the final unmarked symbol
q2 1 Search right for matching final symbol
q2 0 Reject when it is the final unmarked symbol

6.5 Example — 0110

Step 1 — Compare first and last 
0 1 1 0
^     ^

Both are 0.

Mark them: 

X 1 1 X
Step 2 — Compare remaining symbols 
X 1 1 X
  ^ ^

Both are 1.

Mark: 

X Y Y X
Step 3

No unmarked symbols remain. 

XYYX → ACCEPT
Therefore: 
0110 is a palindrome.

Palindrome Rejection Example — 0100

Step 1
0 1 0 0
^     ^

First = 0 and last = 0.

Mark them: 

X 1 0 X
Step 2
X 1 0 X
  ^ ^

Now compare 1 and 0. They are different.

Therefore: 
0100 → REJECT

7. Solved Problem 3 — Equal Number of 0s and 1s

Problem

Construct a TM for strings containing an equal number of 0s and 1s. 

L = { w ∈ {0,1}* | #0(w) = #1(w) }

Examples accepted: 

01
10
0011
0101
1010
1100

Examples rejected: 

0
1
001
011
0001111

7.1 Main idea

Pair every 0 with one 1.

Use: 

X = marked 0
Y = marked 1

Algorithm:

  1. Find an unmarked 0.
  2. Mark it X.
  3. Search for an unmarked 1.
  4. Mark it Y.
  5. Return to the beginning.
  6. Repeat.
  7. If no 0 remains, check that no 1 remains.
  8. If all symbols are marked, accept.

7.2 Example — 0011

Step 1
0 0 1 1
^

Mark first 0: 

X 0 1 1
Step 2

Find one 1 and mark it: 

X 0 Y 1
Step 3

Repeat: 

X X Y Y
All symbols have been paired. 
0011 → ACCEPT

Rejection Example — 001

Step 1
0 0 1

Pair one 0 with the 1: 

X 0 Y
Step 2

There is still an unmarked 0. But there is no unmarked 1 left. 

001 → REJECT

8. Instantaneous Description (ID)

An Instantaneous Description represents the current configuration of a Turing Machine.

A common notation is: 

α q β

where q represents the current state and the machine head is positioned at the first symbol of β.

8.1 Example

0011

Suppose the machine is at the first symbol in q0: 

q0 0011

After marking the first 0: 

X q1 011

The exact ID notation can vary slightly by textbook, but the important point is to show:

  • Tape contents
  • Current state
  • Head position

9. Languages Accepted by Turing Machines

9.1 Accepted language

The language accepted by a TM M is: 

L(M) = { w | M accepts w }

If the machine enters an accept state, the input belongs to the language.

9.2 Rejection

If the machine enters a reject state, the input is not accepted.

9.3 What if the machine never stops?

A Turing Machine may continue forever on some inputs. 

Input
 ↓
TM
 ↓
Runs forever
 ↓
No accept/reject

This is an important difference between a general Turing Machine and a decider.

10. Decidability

10.1 What is a Decidable Language?

A language is decidable if there exists a Turing Machine that halts on every input and correctly answers whether the input belongs to the language.

Such a machine is called a Decider. 

Input
  ↓
Decider
  ↓
 ┌─────────────┐
 │             │
YES           NO
 │             │
HALT          HALT

10.2 Decidable problem

For every input: 

TM eventually halts.

It gives either: 

ACCEPT

 
 REJECT

11. Recursively Enumerable Languages

A language is recursively enumerable (RE), also called Turing-recognizable, if some Turing Machine recognizes it.

For strings belonging to the language: 

 TM eventually accepts.

For strings not belonging to the language, the machine may: 

 reject OR run forever

11.1 Difference between Decider and Recognizer

Feature Decider Recognizer
Member input Accepts and halts Accepts and halts
Non-member input Rejects and halts May reject or loop forever
Always halts? Yes No

12. Decidable vs Recursively Enumerable

Property Decidable RE
Accept members Yes Yes
Reject non-members Yes Not necessarily
Always halts Yes No
Also called Recursive language Turing-recognizable language
Easy memory trick: 
 DECIDER = Always stops RECOGNIZER = May run forever

13. Halting Problem

13.1 Definition

The Halting Problem asks: 

 Given a program P and input w, will P eventually halt on w?

Alan Turing proved that there is no general algorithm that can correctly answer this question for every possible program and input.

13.2 Why is this important?

It demonstrates a fundamental limit of computation.

Some problems cannot be solved by any algorithm that works correctly for every possible input.

Problem 4 — Explain the Halting Problem

Step 1 — Assume a perfect halting machine exists

Suppose we have a machine: 

 H(P, W)

It tells us: 

 YES → P halts on W NO → P does not halt on W
Step 2 — Construct a special program D

D does the opposite of H's prediction when given a program as input. 

 D(P): if H(P,P) says YES: loop forever if H(P,P) says NO: halt
Step 3 — Give D itself as input 
 D(D)

Now two possibilities exist.

Case 1 — H says D halts

Then D is designed to loop forever. Contradiction.

Case 2 — H says D loops forever

Then D is designed to halt. Again contradiction.

Conclusion:

Therefore the assumed perfect machine H cannot exist. The Halting Problem is undecidable.

14. Undecidability

14.1 Meaning

A problem is undecidable if there is no algorithm that correctly solves the problem for every possible input.

14.2 Important undecidable problems

  • Halting Problem
  • Acceptance Problem for Turing Machines
  • Many questions about arbitrary programs

14.3 Decidable vs Undecidable

Decidable Undecidable
There exists an algorithm. No algorithm can solve every instance.
Machine always halts. A general solver cannot always exist.
Example: many finite-state problems. Example: Halting Problem.

15. Acceptance Problem

The acceptance problem asks: 

 Given TM M and input w, does M accept w?

This problem is undecidable for arbitrary Turing Machines.

The reason is closely connected with the ability of a machine to simulate arbitrary computation.

Important distinction: The question: 
 "Does this particular machine accept this particular input?"
is different from asking for a general algorithm that works for every machine and input. The undecidability result concerns the general problem.

16. Important TM Construction Patterns

Pattern 1 — Matching symbols

 Find first 0 ↓ Mark it X ↓ Find matching 1 ↓ Mark it Y ↓ Return ↓ Repeat

Pattern 2 — Palindrome

 Take first symbol ↓ Remember it ↓ Find last symbol ↓ Compare ↓ Mark both ↓ Repeat

Pattern 3 — Counting

 Mark one symbol ↓ Find corresponding symbol ↓ Mark it ↓ Repeat ↓ Check leftovers
