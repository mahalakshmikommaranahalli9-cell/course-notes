1. Introduction to Transport Layer

Understanding the role of the transport layer in process-to-process communication.

What is the Transport Layer?

The Transport Layer is the fourth layer of the OSI model. It provides end-to-end, process-to-process communication between applications running on different hosts.

The network layer is responsible for delivering packets from one host to another. However, a computer may run many applications simultaneously.

Therefore, the transport layer identifies the correct application or process using port numbers.

Position of Transport Layer

Application
↓
Transport
↓
Network
↓
Data Link

The transport layer receives data from the application layer and passes it to the network layer after performing transport-level operations.

Main Responsibilities

  • Process-to-process delivery
  • Service-point addressing using port numbers
  • Segmentation and reassembly
  • Flow control
  • Error control
  • Congestion control
  • Connection management

2. Transport Layer Services

Services provided by the transport layer to applications.

Major Transport Layer Services

  1. Process-to-process delivery – delivers data to the correct application process.
  2. Service-point addressing – uses port numbers to identify applications.
  3. Segmentation – divides large application messages into smaller transport-layer units.
  4. Reassembly – combines received segments to reconstruct the original message.
  5. Flow control – prevents a fast sender from overwhelming a slow receiver.
  6. Error control – detects and handles lost or corrupted data.
  7. Congestion control – reduces traffic when the network becomes congested.

4. User Datagram Protocol (UDP)

A simple connectionless transport protocol.

What is UDP?

UDP (User Datagram Protocol) is a connectionless and lightweight transport-layer protocol.

UDP does not establish a connection before transmitting data. It simply sends datagrams toward the destination.

Characteristics of UDP

  • Connectionless protocol
  • Unreliable delivery
  • No sequencing guarantee
  • No flow control
  • No congestion control
  • Low overhead
  • Fast transmission
  • Uses port numbers

5. Transmission Control Protocol (TCP)

Reliable connection-oriented transport protocol.

What is TCP?

TCP (Transmission Control Protocol) is a connection-oriented, reliable and byte-stream-oriented transport protocol.

TCP establishes a logical connection between sender and receiver before transferring application data.

It provides mechanisms for flow control, error control and congestion control.

Steps in Three-Way Handshake

  2. Server responds with SYN + ACK.
  3. Client sends an ACK.
Result

After these three steps, the TCP connection is established and data transfer can begin.

TCP Connection Termination

TCP normally uses FIN and ACK messages to terminate a connection gracefully.

  1. One side sends FIN.
  2. The other side sends ACK.
  3. The other side sends FIN.
  4. The first side sends ACK.

9. TCP Flow Control

Preventing the sender from overwhelming the receiver.

What is Flow Control?

Flow control is a mechanism that controls the rate at which a sender transmits data so that a receiver can process the incoming data without being overwhelmed.

TCP Sliding Window

10. TCP Error Control

Detection and recovery of lost or corrupted segments.

What is Error Control?

Error control ensures reliable delivery by detecting corrupted or lost segments and retransmitting them when necessary.

TCP Error Control Mechanisms

  • Checksum
  • Sequence numbers
  • Acknowledgements
  • Retransmission
  • Timeout

Acknowledgement

TCP uses acknowledgements to inform the sender that data has been received.

Example

If the receiver has correctly received bytes up to byte 500, it can acknowledge the next expected byte.

Retransmission

If an acknowledgement does not arrive within an appropriate period, TCP assumes that the segment may have been lost and retransmits the data.

11. TCP Congestion Control

Controlling traffic when the network becomes overloaded.

What is Congestion?

Congestion occurs when the amount of data entering a network becomes greater than the network's ability to handle it.

Effects of Congestion

  • Packet loss
  • Longer delays
  • Reduced throughput
  • Retransmissions
  • Network performance degradation

TCP Congestion Control Techniques

  1. Slow Start
  2. Congestion Avoidance
  3. Fast Retransmit
  4. Fast Recovery

Slow Start

TCP initially starts with a small congestion window. The congestion window increases rapidly as successful acknowledgements are received, subject to the applicable congestion-control rules.

cwnd → increases as ACKs arrive

Congestion Avoidance

After the congestion window reaches an appropriate threshold, TCP changes to a slower growth mechanism to reduce the possibility of congestion.

Fast Retransmit

When TCP receives multiple duplicate acknowledgements, it can infer that a segment may have been lost and retransmit it without waiting for the normal timeout.

Fast Recovery

Fast recovery allows TCP to reduce its sending rate after detecting packet loss while avoiding a complete restart of the congestion-control process in applicable TCP variants.

13. Important Exam Questions & Answers

VTU-oriented 2-mark, 5-mark and 10-mark preparation.

⭐ 2-Mark Questions

2 Marks

1. What is the transport layer?

The transport layer is the fourth layer of the OSI model. It provides process-to-process delivery and can provide services such as reliability, flow control, error control and congestion control.

2 Marks

2. What is a port number?

A port number is a logical address used by the transport layer to identify a particular process or application running on a host.

2 Marks

3. What is UDP?

UDP is a connectionless transport-layer protocol that provides a lightweight datagram service without built-in reliable delivery, flow control or congestion control.

2 Marks

4. What is TCP?

TCP is a connection-oriented transport-layer protocol that provides reliable, ordered and full-duplex byte-stream communication.

2 Marks

5. What is flow control?

Flow control is the mechanism used to prevent a fast sender from overwhelming a slower receiver.

2 Marks

6. What is congestion control?

Congestion control regulates the amount of traffic entering the network to reduce overload and packet loss.

⭐ 5-Mark Questions

5 Marks

1. Explain the services provided by the transport layer.

  1. Process-to-process delivery
  2. Service-point addressing
  3. Segmentation and reassembly

2. Explain UDP and its header.

UDP is a connectionless and lightweight transport protocol. It does not establish a connection before transmission and does not provide reliability, flow control or congestion control.

The UDP header contains Source Port, Destination Port, Length and Checksum fields.

5 Marks

3. Explain TCP three-way handshake.

  1. Client sends SYN.
  2. Server responds with SYN + ACK.
  3. Client sends ACK.

After these three steps, the TCP connection is established.

5 Marks

4. Explain TCP flow control.

TCP uses a sliding-window mechanism for flow control. The receiver advertises the amount of buffer space available through the receive window. The sender limits outstanding data according to the advertised window.

2. Explain TCP connection establishment and termination.

Connection Establishment

  1. Client sends SYN.
  2. Server sends SYN + ACK.

Connection Termination

  1. One endpoint sends FIN.
  2. Other endpoint sends ACK.
  3. Other endpoint sends FIN.

10 Marks

3. Explain TCP flow control, error control and congestion control.

Flow Control

Flow control prevents the sender from overwhelming the receiver. TCP uses a receive-window mechanism.

Error Control

TCP uses checksums, sequence numbers, acknowledgements, timeouts and retransmission to provide reliable delivery.

Congestion Control

TCP controls the sending rate when the network becomes congested. Important mechanisms include slow start, congestion avoidance, fast retransmit and fast recovery.

10 Marks

4. Compare TCP and UDP.

TCP is connection-oriented and reliable, whereas UDP is connectionless and provides a lightweight datagram service without built-in reliable delivery.

TCP provides sequencing, acknowledgements, flow control, error control and congestion control. UDP has much lower protocol overhead and is commonly used where low latency or application-controlled reliability is preferred.
