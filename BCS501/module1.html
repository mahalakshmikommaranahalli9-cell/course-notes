1. Software and Software Engineering

What is Software?

Software is a collection of computer programs, procedures, associated data and documentation that performs a specific task or provides a particular service to users.

Definition: Software is a set of instructions and associated data that tells a computer how to perform a task.

Characteristics of Software

  • Software is developed or engineered rather than manufactured.
  • Software does not wear out in the same way as physical hardware.
  • Most software is custom-built for particular requirements.
  • Software can be modified and enhanced.
  • Software complexity can become very high.

Software Engineering

Software engineering is a systematic and disciplined approach to the development, operation and maintenance of software.

Exam point: Software engineering applies engineering principles to software development so that software can be developed systematically and maintained effectively.

2. Unique Nature of WebApps

WebApps are applications delivered through a web browser or web-based environment. They have several characteristics that distinguish them from traditional software applications.

Important WebApp Attributes

  • Network intensive: WebApps normally operate over a network.
  • Content driven: They often provide large amounts of information.
  • Continuous evolution: Web applications may change frequently.
  • Immediacy: New versions and updates can be delivered quickly.
  • Security: WebApps must protect users, data and transactions.
  • Aesthetics: User interface and visual presentation are important.
  • Concurrency: Many users may access a WebApp at the same time.

3. Software Process

A software process is a set of activities, actions and tasks performed to create and maintain software.

Generic Process Framework

Communication → Planning → Modeling → Construction → Deployment

1. Communication

Communication involves interaction with stakeholders to understand requirements, objectives and expectations.

2. Planning

Planning identifies the work to be performed, resources required, schedule, cost and risks.

3. Modeling

Modeling creates analysis and design representations that help developers understand the system.

4. Construction

Construction includes coding and testing the software.

5. Deployment

The software is delivered to users, evaluated and maintained based on feedback.

4. Software Engineering Practice

Software engineering practice provides a disciplined approach for building software.

Major Practice Activities

  1. Understand the problem.
  2. Plan the solution.
  3. Model the requirements and design.
  4. Construct the software.
  5. Test the software.
  6. Deploy and maintain the product.

5. Software Myths

Software myths are incorrect beliefs about software development that can create unrealistic expectations and poor project decisions.

Myth Reality
Requirements can be changed at any time without major impact. Requirement changes can affect cost, schedule and design.
Once the program works, the job is finished. Testing, deployment and maintenance are also important.
Adding more programmers always makes development faster. Additional people can increase communication and coordination effort.

6. Waterfall Model

The Waterfall model is a sequential software process model in which development progresses through well-defined phases.

Requirements → Design → Implementation → Testing → Deployment → Maintenance

Advantages

  • Simple and easy to understand.
  • Phases are clearly defined.
  • Documentation is produced at each stage.
  • Useful when requirements are stable.

Limitations

  • Changes can be difficult after a phase is completed.
  • Working software is produced relatively late.
  • It is less suitable when requirements are uncertain.

7. Incremental Process Model

In an incremental model, the software is developed and delivered in multiple increments.

Increment 1 → Increment 2 → Increment 3 → Complete Product

Each increment provides additional functionality until the complete system is developed.

8. Evolutionary Process Models

Evolutionary models are designed to produce an initial version of software and progressively refine it based on feedback and changing requirements.

Examples

  • Prototyping model
  • Spiral model

9. Concurrent Process Model

The concurrent model represents software development activities as states. Different activities can progress concurrently depending on the status of the project.

Key idea: Different software engineering activities may be performed concurrently rather than strictly one after another.

10. Unified Process

The Unified Process is an iterative and incremental software development process.

Main Phases

  1. Inception: Defines the project scope and business case.
  2. Elaboration: Establishes the architecture and addresses important risks.
  3. Construction: Builds the software functionality.
  4. Transition: Delivers the system to users.

⭐ Important VTU Questions

Q1. Define process and explain the generic process framework for software engineering.

Answer:

A software process is a structured collection of activities, actions and tasks used to develop, deliver and maintain software.

The generic framework consists of five major activities:

  1. Communication – understand stakeholder requirements.
  2. Planning – estimate resources, schedule, cost and risks.
  3. Modeling – create analysis and design models.
  4. Construction – coding and testing.
  5. Deployment – deliver the software and collect feedback.

Q2. Explain the different attributes encountered in WebApps.

Answer:

Important WebApp attributes include:

  • Network intensive
  • Content driven
  • Continuous evolution
  • Immediacy
  • Security
  • Aesthetics
  • Concurrency

Q3. Compare Waterfall model and Spiral model.

Answer:
Waterfall Spiral
Sequential approach Iterative approach
Phases are performed in sequence Development occurs through repeated cycles
Changes can be difficult later Changes can be incorporated during iterations
Less emphasis on repeated risk analysis Risk analysis is a major activity

Q4. Explain software myths.

Answer:

Software myths are false assumptions about software and software development.

Examples include the belief that requirements can always be changed without impact, that a working program means the project is complete, and that adding more programmers always makes a project faster.

Q5. Explain the Waterfall model with advantages and limitations.

Answer:

The Waterfall model follows a sequential development process in which requirements, design, implementation, testing, deployment and maintenance are performed in defined stages.

Advantages:

  • Simple structure.
  • Clear phases.
  • Good documentation.
  • Suitable for stable requirements.

Limitations:

  • Late discovery of problems.
  • Difficult requirement changes.
  • Working software appears relatively late.

Q6. Explain the phases of the Unified Process.

Answer:
  1. Inception – determines project scope and objectives.
  2. Elaboration – develops the architecture and reduces major risks.
  3. Construction – develops the system.
  4. Transition – delivers the system to users.
