1. The Nature of Software

What is Software?

Software is a collection of programs, data and related information that instructs a computer to perform specific tasks.

Software is different from physical products such as machines. It is developed through engineering activities and does not wear out physically like hardware.

Major characteristics of software

  1. Software is developed or engineered; it is not manufactured like hardware.
  2. Software does not physically wear out.
  3. Software is highly flexible and can be modified.
  4. Software is intangible.
  5. Most software is custom-built or customized.
  6. Software becomes increasingly complex as functionality grows.

Software applications

  • System software
  • Application software
  • Engineering/scientific software
  • Embedded software
  • Web applications
  • Artificial intelligence software
  • Cloud applications
Remember: Software is intangible, engineered rather than manufactured, and does not physically wear out.

2. Unique Nature of WebApps

Web applications are software applications that are accessed through a network using browsers or other web-enabled clients.

Important characteristics

Characteristic Explanation
Network intensive WebApps depend on networks and Internet/Intranet connectivity.
Concurrency Many users may access the application simultaneously.
Unpredictable load The number of users can change significantly.
Performance Response time is important for user satisfaction.
Availability Users expect WebApps to remain available.
Security WebApps must protect user data and services.
Aesthetics Interface design and visual presentation affect usability.
Continuous evolution WebApps are frequently updated and enhanced.
VTU exam: "Explain the different attributes encountered in the vast majority of WebApps."

3. Software Engineering

Software Engineering is a systematic, disciplined and measurable approach to the development, operation and maintenance of software.

Objectives

  • Develop reliable software.
  • Meet customer requirements.
  • Control development cost.
  • Deliver software within planned time.
  • Improve maintainability.
  • Improve quality.

Software Engineering vs Programming

Programming Software Engineering
Mainly focuses on writing code. Covers the complete software lifecycle.
Usually smaller scope. Suitable for large and complex systems.
Less emphasis on management. Includes planning, quality, risk and maintenance.

4. Software Engineering Practice

Software engineering practice provides the technical activities required to build high-quality software.

Seven principles of software engineering practice

  1. Divide and conquer: Solve a large problem by dividing it into smaller problems.
  2. Understand the problem: Clearly understand requirements before designing a solution.
  3. Use an effective approach: Select suitable methods and tools.
  4. Build quality into the solution: Quality should be considered throughout development.
  5. Produce effective representations: Models and diagrams help communicate the solution.
  6. Maintain consistency: Keep requirements, design and implementation consistent.
  7. Review the result: Examine the work to identify defects and improvements.

5. Software Myths

Software myths are incorrect beliefs about software development. They can create unrealistic expectations and poor decisions.

Customer myths

  • "A general statement of objectives is enough to start coding."
  • "Changes can be made easily at any time."

Management myths

  • "If a project is late, adding more programmers will always make it faster."
  • "Existing standards and procedures automatically guarantee success."

Practitioner myths

  • "Once the program runs, the job is finished."
  • "Quality cannot be evaluated until the program executes."
Exam point: A myth sounds reasonable but does not represent the reality of professional software development.

6. Software Process

A software process is a set of activities, actions and tasks performed to develop and maintain software.

Framework activities

Communication Planning Modeling Construction Deployment

Umbrella activities

  • Software project tracking and control
  • Risk management
  • Software quality assurance
  • Technical reviews
  • Configuration management
  • Measurement
  • Documentation

7. Generic Process Model

A generic process model provides a common framework for organizing software engineering activities.

COMMUNICATION ↓ PLANNING ↓ MODELING ↓ CONSTRUCTION ↓ DEPLOYMENT ↓ FEEDBACK

1. Communication

Developers communicate with stakeholders to understand requirements, objectives and constraints.

2. Planning

The team estimates resources, cost, schedule and activities.

3. Modeling

Requirements and design models are created to understand the solution.

4. Construction

Coding and testing are performed.

5. Deployment

The completed software is delivered to users and feedback is collected.

VTU 10-mark question:
Define process and explain the generic process framework for software engineering.

8. Process Assessment and Improvement

Process assessment examines the existing software development process to identify strengths, weaknesses and areas for improvement.

General steps

  1. Assess the current process.
  2. Identify problems.
  3. Analyze possible improvements.
  4. Introduce improved practices.
  5. Measure the results.
  6. Continue improvement.

9. Waterfall Model

The Waterfall model is a sequential software process model in which development activities proceed through defined phases.

Requirements ↓ System Design ↓ Implementation ↓ Testing ↓ Deployment ↓ Maintenance

Advantages

  • Simple and easy to understand.
  • Clearly defined phases.
  • Easy to manage when requirements are stable.
  • Documentation is produced throughout the process.

Disadvantages

  • Difficult to accommodate changing requirements.
  • Working software appears relatively late.
  • Testing occurs after implementation.
  • Risk of discovering requirement problems late.

10. Incremental Process Model

The incremental model develops software through multiple smaller releases called increments.

Requirements ↓ Increment 1 → Working Product ↓ Increment 2 → More Features ↓ Increment 3 → More Features ↓ Final Product

Advantages

  • Early delivery of working software.
  • Customer feedback can be obtained early.
  • Important features can be delivered first.
  • Changes can be incorporated into later increments.

11. Evolutionary Process Models

Evolutionary models produce an initial version of the software and then evolve it based on feedback and changing requirements.

Prototyping

A prototype is an early version of a software system used to understand requirements and obtain feedback.

Spiral Model

The Spiral model combines iterative development with systematic risk analysis.

Planning ↓ Risk Analysis ↓ Engineering ↓ Customer Evaluation ↺ Next Spiral

Advantages of Spiral Model

  • Strong focus on risk management.
  • Suitable for large and complex projects.
  • Customer feedback is incorporated.
  • Software evolves through repeated cycles.

Disadvantages

  • Can be expensive.
  • Requires risk-analysis expertise.
  • May be difficult for small projects.

12. Concurrent Development Model

The concurrent development model represents software activities as states that can occur concurrently.

Activity ↓ Under Development ↓ Under Review ↓ Completed ↓ Changes Required ↺

Different engineering activities may progress at different rates. This model is useful when several activities need to proceed simultaneously.

13. Specialized Process Models

Component-Based Development

Existing reusable software components are selected, adapted and assembled to construct a system.

Formal Methods

Mathematical techniques are used to specify and verify software.

Aspect-Oriented Development

Cross-cutting concerns such as security, logging and error handling are separated from the main application logic.

14. Unified Process

The Unified Process is an iterative software development process. It organizes development into four major phases.

Inception Elaboration Construction Transition

Inception

Defines project scope, objectives and initial business requirements.

Elaboration

Analyzes requirements and establishes the architectural foundation.

Construction

Software components are implemented and tested.

Transition

The software is delivered to users and deployment issues are addressed.

15. Personal Software Process (PSP)

PSP is a disciplined process that helps an individual software engineer improve planning, estimation, quality and productivity.

PSP activities

  • Planning
  • Design
  • Code
  • Compile
  • Test
  • Postmortem analysis

Benefits

  • Improves individual productivity.
  • Improves estimation.
  • Helps track defects.
  • Encourages disciplined development.

16. Team Software Process (TSP)

TSP is a structured process that helps software teams plan, manage and control their development work.

Important characteristics

  • Team planning
  • Defined responsibilities
  • Measurement
  • Quality management
  • Project tracking
  • Continuous improvement

PSP vs TSP

PSP TSP
Focuses on an individual engineer. Focuses on the complete team.
Individual planning. Team planning.
Individual quality measurement. Team quality and project measurement.

📊 Important Process Model Comparison

Model Main Idea Suitable For

Incremental Multiple working releases Early delivery
Spiral Iteration + risk analysis Large/high-risk systems
Prototyping Early model for feedback Unclear requirements
Concurrent Activities progress concurrently Parallel development
Unified Process Iterative and incremental Large object-oriented systems
